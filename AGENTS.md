# Правила работы с OpenVerse

## Архитектура

- Frontend зависит от backend: шаблоны, JavaScript и CSS могут использовать
  публичные HTTP- и WebSocket-контракты backend.
- Backend не зависит от frontend. Backend-код не должен импортировать,
  анализировать или требовать наличия шаблонов, JavaScript, CSS или другой
  реализации пользовательского интерфейса.
- Исключение — WebSocket-маршруты и их публичный контракт: backend предоставляет
  события и сообщения, а frontend может на них подписываться.

## Backend

- Перед изменением backend-кода сначала описать пользователю предлагаемые
  изменения и дождаться явного одобрения.
- Если пользователь явно указал, что и где нужно изменить в backend, внести эти
  изменения без дополнительного запроса на подтверждение.

## Исключения

- Все пользовательские исключения проекта размещать в `src/exc.py`.
- Новые исключения оформлять в едином со стилем этого файла виде: осмысленное
  имя, общий базовый класс проекта при необходимости и без дублирования
  существующих исключений.

## Проверки

- После изменений Python-кода запускать Ruff для затронутых файлов.
- Не подавлять правила Ruff без обоснования и согласования с пользователем.

## Стиль кода

- По возможности использовать идиоматичный синтаксический сахар и возможности
  языка, если это сохраняет читаемость кода.
- Не использовать `getattr` и `setattr` для обычной работы с атрибутами.
  Предпочитать прямой и типобезопасный синтаксис: `obj.attribute` и
  `obj.attribute = value`.
- Соблюдать единый стиль оформления и именования во всех изменяемых файлах.

## Изменения без override-слоёв

- Не создавать в CSS и HTML дополнительные override-слои, дублирующие или
  перекрывающие уже существующие классы и стили.
- Не добавлять в backend повторные обработчики, зависимости, функции или другие
  слои, предназначенные для перекрытия предыдущей реализации.
- Если существующая реализация должна измениться, отредактировать или удалить
  исходный класс, стиль или код вместо добавления override-реализации.

## Правила модуля python
